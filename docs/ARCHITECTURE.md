# Architecture

OpenNotebook Studio runs Next.js, FastAPI, an arq worker, an embedding HTTP service, PostgreSQL with pgvector, and Redis. API and worker share the `opennotebook-core` interfaces for storage, embedding, and LLM calls. See [DECISIONS.md](DECISIONS.md) for version-specific choices.

Better Auth lives in Next.js and owns `user`, `session`, `account`, `verification`, `jwks`, and `rateLimit` tables. The browser uses its session cookie to obtain a 15-minute JWT and sends that token directly to FastAPI. FastAPI verifies JWKS and scopes every notebook, source, and settings query by the JWT subject. App tables have no foreign key to Better Auth tables. Better Auth CLI migrates auth tables; Alembic migrates app tables.

Users add PDF, DOCX, PPTX, TXT, MD, pasted text, or website sources to a notebook. FastAPI checks ownership and limits, stores uploaded bytes through `StorageBackend`, creates a `sources` row and persisted job, then enqueues `ingest_source` in Redis. The worker fetches or reads bytes, extracts structured text blocks, makes sentence-safe chunks with offsets into the stored canonical text, embeds them in batches, and atomically replaces that source's chunks. Progress stages are `fetching`, `extracting`, `chunking`, `embedding`, `indexing`, and `ready`; failures are visible and retryable. Redis pub/sub carries status updates to the API's owned SSE stream, and the browser reconnects with a fresh JWT. A snapshot query on reconnect closes gaps while the stream was offline.

`sources` records the embedding model and dimension. `chunks` stores the vector, exact character range, page range, heading path, and full-text `tsvector`; PostgreSQL indexes vectors with HNSW cosine and text with GIN. The worker refuses an index write when another source in the notebook has a different model identity. A notebook reindex computes every replacement vector before committing all model and vector changes in one transaction. Changing the physical vector dimension additionally requires a deployment migration.

The embedding service loads `google/embeddinggemma-2` once with vision and audio towers disabled, FP32 CPU inference, correct retrieval prompts, Matryoshka truncation, and unit normalization. A persistent cache volume holds the checkpoint; `fake` remains available for deterministic tests. Website fetches validate scheme, port, redirect targets, and all resolved IPs; the resolver pins approved public addresses to the connection. Responses have byte and time limits. Files have an extension allowlist, content checks, and a 50 MB cap; notebooks have a 50-source cap and PDFs a 500-page cap.

User settings store provider-native model IDs and a Fernet-encrypted map of provider keys. A personal key overrides the matching server key; OpenRouter uses `OPENROUTER_API_KEY` by default. `/settings/models` fetches live provider lists. `DEFAULT_CHAT_MODEL` and `DEFAULT_CHEAP_MODEL` are environment defaults.

Chat reads only selected, ready sources in the caller's notebook. Short notebooks use full context; larger ones use query embeddings, PostgreSQL full-text ranking, RRF, and eight excerpts. The API sends a versioned grounded prompt to the selected provider and streams SSE tokens. It then validates citation labels against the exact excerpts sent, stores the final answer and model, and sends structured citations and follow-up questions. A browser abort closes the upstream model stream. Redis enforces a per-user chat limit, and a shared semaphore caps LLM concurrency. `chat_messages` is owned by Alembic and never references auth tables.
